# 实现范围与验收标准

本目录描述当前云端实现，不代表 Epic 网站上的真实领取已验证。

## 架构

Go 服务提供嵌入式中文管理界面、Bearer 认证 API、SQLite 持久化、单消费者队列与计划调度。独立 Node/Playwright Worker 通过 stdin/stdout JSON 接收一个账号和确定的 offer 列表。Worker 使用每账号标签隔离的本地浏览器会话；尚未绑定/验证 Epic account ID，用户必须自行检查登录身份；Go 服务不保存密码、TOTP、验证码或 cookies。

## 安全边界

1. 发现阶段要求明确数值零价格、当前活动窗口和唯一 namespace/offer。
2. 领取阶段检查账号当前拥有状态，随后核对 checkout 的唯一 offer 身份、游戏名称、最终数值总价及税额。
3. 价格变化、未知字段/页面、登录、CAPTCHA、二次验证和条款阻塞均失败关闭。
4. 即将提交时再次检查当前 checkout，不依赖商品页 Free 标记。
5. 完成订单后重新载入商品页并验证拥有；感谢页面不是成功证据。
6. 进程超时、异常退出和重启中断均保留不确定状态，必须人工核查和明确恢复。
7. 不使用隐身插件、CAPTCHA 求解器、检测规避、私有支付接口或 AI 凭据处理。

## 队列与存储

数据库通过 UNIQUE(account_id, namespace, offer_id) 合并所有手动和自动发现。Go 以数据库级 OS 文件锁限制单实例，SQLite 事务原子取得待执行任务。已完成、人工阻塞和不确定任务不会因再次检查而重新排队。后续不重叠促销窗口会刷新未完成任务的过期活动信息，明确失败任务可在新周期重新排队；人工阻塞及不确定状态仍需明确恢复。已知安全失败采用最多三次尝试；显式重试重置尝试计数。

当前面向 Linux 单机，数据库不可放在共享网络文件系统供多个副本使用。数据库和会话卷需可信系统用户私有访问。早期仓库数据库是空桩，没有旧版实际数据迁移；后续 schema 升级需要增加迁移版本。

## 验收

- Go 单元测试：账号保存、权限、请求校验、重复触发、调度、人工门槛、重启、锁、失败退避
- HTTP handler 到真实 SQLite/调度器的离线集成测试；Worker 使用内存 fixture
- Node 测试：价格解析、身份、活动窗口、下单前再次检查、拥有验证和阻塞状态
- 不在自动测试中登录或领取真实游戏

## 明确尚未实现

远程图形登录托管、HTTP Worker、通知发送、代理管理、密码托管、多副本高可用、完整历史分页、真实 Epic 端到端验证和真实容器部署。登录工具只提供可信本地浏览器入口；某些挑战必须人工完成整次领取，程序不能保证人工挑战之后无头流程一定恢复。
